# Безопасность

Активы: личные контакты/заметки, семейная база, граф, источники и содержимое AI-предложений, пароли/сессии. Угрозы: неавторизованный интернет-клиент, чужой участник Family, ограниченный импортёр, утечка бэкапа/репозитория, ошибочный SQL-фильтр, конкурентное изменение.

Контрмеры: Argon2id; случайные серверные session tokens (в DB SHA-256); HttpOnly/SameSite=Strict, Secure и __Host prefix на HTTPS; Origin + session-bound CSRF; 12 попыток на аккаунт/15 мин и 80 на IP, дополнительные nginx limits. Logout и revoke-all удаляют серверные сессии. Смена пароля требует текущего пароля и CSRF, блокирует строку пользователя и отзывает все его сессии. Login использует ту же row lock до commit: проверенный старый пароль не может создать сессию после завершившейся смены. Bootstrap интерактивный, только пока users пуст. Публичной регистрации нет. Приглашение одноразовое, 72 часа, привязано к email. Существующий пользователь должен подтвердить пароль.

Роли проверяются сервером на каждом запросе. Viewer не пишет; editor не приглашает; admin приглашает в Family. Personal не выдаётся чужим пользователям; DB-триггер запрещает их членство. Составные FK и FORCE RLS защищают связанные данные. Токены импорта ограничены user/workspace, expiry и двумя POST-операциями; не читают контакты и не подтверждают AI.

SQL параметризован. React экранирует текст; HTML из заметок не рендерится. URL только http/https, без credentials. CSP запрещает внешние скрипты/frames; inline styles нужны компонентам/Cytoscape. Запросы ограничены 256 KiB, списки и граф — лимитами. Backend access-log отключён, не логировать тела/токены. Audit хранит метаданные, UPDATE/DELETE runtime запрещены. Secrets не входят в образ; Compose env вне Git. Runtime-роль не superuser/BYPASSRLS. Контейнеры api/web non-root, read-only, cap_drop ALL, no-new-privileges. DB отдельная internal network, публичных портов нет.

Остаточные риски: MFA пока отсутствует; для небольшой закрытой семьи предусмотрен длинный случайный пароль и rate limits; при расширении доступа рекомендуется WebAuthn/TOTP либо внешний identity-aware proxy. RLS не защищает от полного захвата backend, который может устанавливать workspace context. PostgreSQL volume не шифруется приложением — нужна защита диска хоста. Метаданные audit доступны администраторам workspace. Приглашения передаются владельцем по доверенному каналу. Shared nginx-to-api IP ограничивает вход суммарно для всех клиентов: безопасный, но консервативный предел, не основание бездумно доверять X-Forwarded-For. Прикладного rate limit для всех bearer-операций нет вне nginx; API должен оставаться внутренним.

Сканер секретов не гарантирует отсутствие ПДн: нужен осмотр исходников и истории перед публичным push. Проверки и их реальные результаты — VALIDATION.md. Никакого утверждения о полной защищённости.

## Временное исключение аудита зависимости сборки

2026-11-17 GitHub Advisory Database обновила [GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf): ReDoS в picomatch≤4.0.7 при атакующих extglob patterns. Исправленной опубликованной версии нет; npm view показывает4.0.7. Это **известная неисправленная уязвимость зависимости сборки**, а не «ноль уязвимостей». Пять npm findings — одна причина и её цепочка Vite/tinyglobby/fdir/plugin-react.

В CRM picomatch — только dev dependency Vite. В финальном frontend image Nginx и static dist, нет Node/npm/node_modules; API — Python. Приложение не принимает glob patterns от пользователей, сборка работает с контролируемым исходным кодом. Не открывать Vite dev server в интернет и не превращать пользовательский ввод в build globs. Поэтому данный путь атаки не достижим через размещённый CRM; сборочный риск остаётся. Не понижать Vite до старой major ради автоматического npm audit fix.

`scripts/audit-frontend.mjs` отдельно строго проверяет runtime dependencies и полный audit. До **2026-12-17 (исключительно)** допускается только указанный GHSA на picomatch4.0.7 и его транзитивной цепочке, при dev=true у каждого узла lockfile. Все другие high/critical findings, продвижение зависимости в runtime, смена версии, истечение срока и ошибки аудита блокируют CI. Полный отчёт и предупреждение остаются в CI output. После исправления upstream обновить lockfile, проверить сборку и удалить исключение; если исправления к сроку нет — требуется новая оценка, автоматического продления нет.
