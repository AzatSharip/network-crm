# Безопасность

Активы: личные контакты/заметки, семейная база, граф, источники и содержимое AI-предложений, пароли/сессии. Угрозы: неавторизованный интернет-клиент, чужой участник Family, ограниченный импортёр, утечка бэкапа/репозитория, ошибочный SQL-фильтр, конкурентное изменение.

Контрмеры: Argon2id; случайные серверные session tokens (в DB SHA-256); HttpOnly/SameSite=Strict, Secure и __Host prefix на HTTPS; Origin + session-bound CSRF; 12 попыток на аккаунт/15 мин и 80 на IP, дополнительные nginx limits. Logout и revoke-all удаляют серверные сессии. Смена пароля требует текущего пароля и CSRF, блокирует строку пользователя и отзывает все его сессии. Bootstrap интерактивный, только пока users пуст. Публичной регистрации нет. Приглашение одноразовое, 72 часа, привязано к email. Существующий пользователь должен подтвердить пароль.

Роли проверяются сервером на каждом запросе. Viewer не пишет; editor не приглашает; admin приглашает в Family. Personal не выдаётся чужим пользователям; DB-триггер запрещает их членство. Составные FK и FORCE RLS защищают связанные данные. Токены импорта ограничены user/workspace, expiry и двумя POST-операциями; не читают контакты и не подтверждают AI.

SQL параметризован. React экранирует текст; HTML из заметок не рендерится. URL только http/https, без credentials. CSP запрещает внешние скрипты/frames; inline styles нужны компонентам/Cytoscape. Запросы ограничены 256 KiB, списки и граф — лимитами. Backend access-log отключён, не логировать тела/токены. Audit хранит метаданные, UPDATE/DELETE runtime запрещены. Secrets не входят в образ; Compose env вне Git. Runtime-роль не superuser/BYPASSRLS. Контейнеры api/web non-root, read-only, cap_drop ALL, no-new-privileges. DB отдельная internal network, публичных портов нет.

Остаточные риски: MFA пока отсутствует; для небольшой закрытой семьи предусмотрен длинный случайный пароль и rate limits; при расширении доступа рекомендуется WebAuthn/TOTP либо внешний identity-aware proxy. RLS не защищает от полного захвата backend, который может устанавливать workspace context. PostgreSQL volume не шифруется приложением — нужна защита диска хоста. Метаданные audit доступны администраторам workspace. Приглашения передаются владельцем по доверенному каналу. Shared nginx-to-api IP ограничивает вход суммарно для всех клиентов: безопасный, но консервативный предел, не основание бездумно доверять X-Forwarded-For. Прикладного rate limit для всех bearer-операций нет вне nginx; API должен оставаться внутренним.

Сканер секретов не гарантирует отсутствие ПДн: нужен осмотр исходников и истории перед публичным push. Проверки и их реальные результаты — VALIDATION.md. Никакого утверждения о полной защищённости.
