# Поиск

Поисковый документ обновляется сервисом сохранения в той же транзакции, что карточка. Он объединяет имя/ФИО, альтернативные имена, географию, профессию, компетенции, описание/заметки, исходные и нормализованные идентификаторы, подписи, теги, названия организаций и должности.

Generated tsvector: русское имя вес A, русский документ B, simple-документ C. GIN по tsvector и GIN pg_trgm по search_text. Запрос разбивается максимум на 12 слов (до 200 символов), для каждого текстового слова требуется русское FTS, simple FTS, частичное ILIKE либо trigram word similarity >= 0.45. Нечёткое сопоставление применяется только от 4 символов. Идентификаторы с цифрами, @, точками и URL-разделителями ищутся частично без FTS/fuzzy, чтобы общий домен email не давал ложных совпадений. Слова могут находиться в разных атрибутах. Регистр не учитывается. `%`/`_` и SQL-подобные строки трактуются как данные. Фильтры city/country/profession точные без регистра, tag точный, priority личный, known_by по связи участника.

Ранжирование: точное имя, точный нормализованный контактный идентификатор, затем ts_rank_cd, затем similarity имени; стабильное завершение сортировки по display_name и id. Частичные идентификаторы находятся через документ. Нормализация контактных методов описана в DATA_MODEL.

Каждый запрос ограничен проверенным workspace, дополнительно действует RLS. Ответ содержит total, page, size, items. Пагинация серверная, UI debounce 250 мс и защита от устаревших ответов.

Benchmark на 10 000 синтетических карточек (PostgreSQL 18.6, локальный Colima, HTTP in-process, 5 замеров после прогрева): точное имя 31 мс, точный email 40 мс, Уфа + стоматология 89 мс, компания 41 мс, широкий запрос с опечаткой 259 мс. Это локальные измерения, не SLA интернет-сервиса. Полные результаты и EXPLAIN ANALYZE/BUFFERS — search-benchmark.json.
