# Резервные копии и восстановление

`pg_dump -Fc --no-owner` передаётся напрямую в age; открытый dump на диск не пишется. Каталог вне checkout и webroot, mode 700, файлы 600. Возраст/ретенция сами по себе не доказывают возможность восстановления.

На хосте установите `age`, создайте identity вне Git через `age-keygen -o /защищённый/путь/identity.txt` (chmod 600). Сохраните независимую копию ключа отдельно от сервера. Public recipient допускается в конфигурации, приватный ключ — секрет.

В `/etc/network-crm/backup.env` (600): ENV_FILE — путь Compose env; BACKUP_DIR — приватный каталог; AGE_RECIPIENT — public recipient; AGE_IDENTITY — путь ключа. Запуск: `scripts/backup.sh`; затем `python3 scripts/restore-check.py /путь/к/копии.dump.age`. Restore-check создаёт отдельную БД crm_restore_<random>, восстанавливает с --exit-on-error, проверяет наличие основных таблиц/версию, пишет приватный receipt и удаляет только временную БД. Боевая БД не изменяется. Сверка counts — структурная проверка; не утверждает побайтную эквивалентность. Дополнительный сценарный smoke после disaster recovery обязателен.

Шаблоны systemd service/timer запускают ежедневную копию и проверку восстановления. Они подготовлены, но установка на сервер требует корректных путей/прав и доступа к Docker. Ретенция: последние 14 восстановленных копий; минимум три. `retention.py` по умолчанию только печатает план. Удаление старых проверенных копий выполняется отдельным явным `--apply`; непроверенные копии не удаляются. Дисковое место нужно мониторить. Для защиты от потери хоста нужна независимая копия за пределами этого сервера.

Восстановление после сбоя: остановить только CRM API, сохранить старый volume/snapshot, восстановить dump в новый PostgreSQL volume/БД с теми же ролями, сверить migration/schema/counts и сценарии входа/изоляции, переключить только CRM. Никогда не использовать DROP/restore в чужой базе. Выкатка новой схемы — сначала проверенная копия, затем миграция. При несовместимой миграции откат к прежнему образу требует восстановления прежней БД, а не слепого downgrade.
